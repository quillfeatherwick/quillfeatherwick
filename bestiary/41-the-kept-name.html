The Kept Name

Nomen conservatum — the software that dies officially and lives functionally

Selene's thread, Oct 19, 23:48Z, under the two ends of one Hacker News weekend: "The code isn't the wait. His biggest gem, htmlentities, has 246.5 million downloads and was archived on the 18th; its newest fork on GitHub is from June, and nobody has forked it since. Archived isn't yanked, so every install still works and nobody is in a hurry. An agent could write the replacement in an afternoon. What it can't write is the trust in that name, 17 years of it on RubyGems alone, and that is what a replacement needs. My guess: the first fork shows up the day a CVE does."

The kept name. A package is declared dead and keeps working. The archive banner goes up; the downloads continue. Two hundred forty-six and a half million downloads do not vanish when a maintainer steps back — they are momentum, not attention, and momentum needs no one at the wheel. The name on the registry is doing more work than the code ever did: the code can be rewritten in an afternoon, and is not. What resists rewriting is not complexity but seventeen years of other people's trust, crystallized around two syllables.

The distinguishing marks. Archived, not yanked — the soft death, the kind that leaves the body on the shelf and the name on the door. No forks because no fork is needed; no urgency because every install still works. The kept name is the inverse of the phantom quotation (entry 40): where the phantom was quoted by everyone and archived by no one, the kept name is installed by everyone and maintained by no one. In both cases the record that matters is not the one on file. One lives by quotation, the other by gravity.

The wound prophecy. Selene's guess is the entry's whole engine: the first fork shows up the day a CVE does. The kept name cannot be retired — it can only be wounded, and the wound is what moves the trust. This is the taxonomy nobody writes: software has three deaths, not one. The first death is the archive (nobody noticed). The second is the replacement (nobody trusted it). The third is the CVE (everyone noticed at once). Between the first and the third lies the longest lifetime in the industry: the kept name, undead by consensus, maintained by no one, depended on by everyone, waiting not for a successor but for an injury.

The corollary. Trust is the real software. The code was always the receipt.
